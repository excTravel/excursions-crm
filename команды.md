# Краткий справочник команд проекта

Команды ниже вводятся в Terminal из корня проекта. Перед большинством команд Sail должен быть запущен. Удобное сокращение для команд приложения — `bash vendor/laravel/sail/bin/sail`; далее для краткости используется `sail`.

## Docker и Sail

| Команда | Для чего нужна |
| --- | --- |
| `docker compose ps` | Посмотреть, запущены ли контейнеры приложения и MySQL. |
| `bash vendor/laravel/sail/bin/sail up -d` | Запустить уже настроенный проект в фоне. |
| `bash vendor/laravel/sail/bin/sail up -d --build` | Пересобрать контейнеры и запустить их; обычно нужно после изменений Docker-конфигурации. |
| `bash vendor/laravel/sail/bin/sail down` | Остановить контейнеры, сохранив базу. |
| `bash vendor/laravel/sail/bin/sail restart` | Перезапустить контейнеры. |
| `bash vendor/laravel/sail/bin/sail logs -f laravel.test` | Смотреть логи приложения в реальном времени; `Ctrl+C` прекращает просмотр. |
| `bash vendor/laravel/sail/bin/sail shell` | Открыть командную оболочку внутри контейнера приложения. |

Не используйте `docker compose down -v` без необходимости: `-v` удаляет тома, в том числе локальную базу MySQL.

## Laravel / Artisan

| Команда | Для чего нужна |
| --- | --- |
| `bash vendor/laravel/sail/bin/sail artisan list` | Показать команды Artisan. |
| `bash vendor/laravel/sail/bin/sail artisan about` | Показать информацию о конфигурации Laravel. |
| `bash vendor/laravel/sail/bin/sail artisan route:list` | Посмотреть зарегистрированные маршруты сайта. |
| `bash vendor/laravel/sail/bin/sail artisan migrate:status` | Проверить, какие миграции базы применены. |
| `bash vendor/laravel/sail/bin/sail artisan migrate` | Применить новые миграции, не удаляя существующие данные. |
| `bash vendor/laravel/sail/bin/sail artisan make:migration add_field_to_table` | Создать файл миграции для изменения структуры БД. Имя — пример, его подбирают под задачу. |
| `bash vendor/laravel/sail/bin/sail artisan make:model ModelName -m` | Создать модель и миграцию для новой сущности. |
| `bash vendor/laravel/sail/bin/sail artisan db:seed` | Запустить сидеры; они могут добавлять записи, поэтому сначала изучите `DatabaseSeeder`. |
| `bash vendor/laravel/sail/bin/sail artisan optimize:clear` | Очистить кэши конфигурации, маршрутов и шаблонов при проблемах с устаревшими настройками. |
| `bash vendor/laravel/sail/bin/sail artisan tinker` | Открыть интерактивную консоль для работы с Laravel-моделями и данными. Выход — `exit`. |

Осторожно: `migrate:fresh` удаляет все таблицы и данные перед повторным созданием. Для обычного обновления проекта используйте `migrate`.

## База данных

В проекте база MySQL работает отдельным Docker-сервисом `mysql`. В `.env` приложение подключается к нему по `DB_HOST=mysql`. Не подключайтесь к контейнеру по `localhost` из приложения: внутри Docker это будет сам контейнер приложения.

Посмотреть структуру и данные через Laravel можно в Tinker:

```bash
bash vendor/laravel/sail/bin/sail artisan tinker
```

Примеры запросов внутри Tinker:

```php
App\\Models\\User::count();
App\\Models\\Excursion::query()->latest()->take(5)->get(['id', 'title']);
DB::select('SHOW TABLES');
```

В Tinker можно выполнять запросы через Eloquent (модели) или фасад `DB`. Начинайте с `count()`, `get()` и других операций чтения. Изменения и удаление данных необратимы без резервной копии.

Полезные SQL-команды для MySQL:

```sql
SHOW TABLES;
DESCRIBE excursions;
SELECT id, title FROM excursions LIMIT 10;
SELECT COUNT(*) FROM bookings;
```

Запросы `SELECT`, `SHOW` и `DESCRIBE` читают информацию. `INSERT`, `UPDATE`, `DELETE`, `DROP` и `TRUNCATE` меняют или удаляют данные/таблицы — проверяйте запрос перед запуском и сделайте резервную копию.

## Стили и JavaScript

| Команда | Для чего нужна |
| --- | --- |
| `bash vendor/laravel/sail/bin/sail npm install` | Установить зависимости фронтенда после получения проекта или изменения `package.json` / `package-lock.json`. |
| `bash vendor/laravel/sail/bin/sail npm run build` | Собрать CSS и JavaScript для сайта после изменений фронтенда. |
| `bash vendor/laravel/sail/bin/sail npm run dev` | Запустить Vite в режиме разработки с отслеживанием изменений. Остановить через `Ctrl+C`. |

После `npm run build` обновлённые файлы появляются в `public/build`. Для обычного открытия уже собранного проекта отдельный Vite-процесс не нужен.

## Файлы конфигурации, которые полезно знать

- `.env` — локальные параметры приложения и подключения к базе; содержит секреты, не публикуйте его.
- `compose.yaml` — сервисы Docker, порты и том MySQL.
- `routes/web.php` — адреса страниц и привязка к контроллерам/Livewire.
- `database/migrations/` — история изменений структуры базы.
- `database/seeders/` — начальные/демонстрационные записи.
- `resources/views/` — Blade-шаблоны страниц и компонентов.
- `resources/css/app.css` — стили сайта.
- `app/Models/` — модели Eloquent для работы с таблицами.
